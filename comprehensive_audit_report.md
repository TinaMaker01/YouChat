# Comprehensive Project Audit Report - Messenger App

This report outlines the identified problems, risks, and recommended improvements for the Messenger application, prioritized by their impact on security, stability, and user experience.

| Priority | Description | Impact | Recommended Solution | Estimated Effort |
| :--- | :--- | :--- | :--- | :--- |
| **Critical** | **Broken Linting Environment:** Missing `eslint-config-next` dependency and unconfigured flat ESLint environment. | High: Prevents automated code quality checks, allowing syntax errors and anti-patterns to reach production. | Install missing dependencies with `npm install --legacy-peer-deps` and verify `npm run lint` passes. | Low |
| **High** | **Missing Input Validation:** Absence of robust, schema-based validation (e.g., Zod) for API payloads and Server Action arguments. | High: Increases vulnerability to malformed data, injection attacks, and inconsistent database states. | Centralize schemas in `src/lib/validations.ts` and apply validation to all Auth and Messaging endpoints. | Medium |
| **High** | **Scalability & Technical Debt:** Reliance on 3-second client-side polling for real-time messaging updates. | High: Excessive server load and poor scalability. Leads to a sub-optimal "real-time" experience compared to WebSockets. | Replace polling with a WebSocket-based solution (Socket.io or Pusher) for instant, event-driven updates. | High |
| **Medium** | **Insufficient Test Coverage:** Critical business logic in authentication and API access control lacks automated unit/integration tests. | Medium: High risk of regressions during architectural changes or refactoring. | Expand the Vitest test suite to cover `src/lib/auth.ts` and protected routes in `src/app/api/`. | Medium |
| **Medium** | **Placeholder Search Functionality:** The search bar in the conversation sidebar is present in the UI but currently non-functional. | Medium: Poor user experience for power users with numerous active conversations. | Implement client-side filtering in `ChatSidebar.tsx` to dynamically search the conversations list. | Low |
| **Medium** | **Static/Hardcoded Timestamps:** Message and conversation timestamps do not update dynamically or show relative "time ago" formats. | Low: User experience is less intuitive as users cannot easily see how fresh a message is. | Implement a relative timestamp utility in `src/lib/utils.ts` using `Intl.RelativeTimeFormat` and update UI. | Low |
| **Low** | **Unused Legacy Artifacts:** Presence of unused components (e.g., from previous blog iterations) and legacy SQL commands in `db-init.ts`. | Low: Increases codebase clutter and maintainability overhead. | Perform a cleanup of unused files in `src/components/` and refactor `db-init.ts` for clarity. | Low |
